# MVP triage: 5 блоков и критерии «готово»

Интернет-магазин. Обращения приходят текстом (не живые почта / форма / чат).  
Сервис классифицирует, пишет черновик и сохраняет аудит. Один endpoint.

Стек: Python 3.10+ / FastAPI, OpenAI, SQLite, Docker.

- Endpoint: `POST /triage`
- Категории: `billing` | `support` | `complaint` | `other`
- Лимит: N запросов в минуту на `client_id`
- Temperature LLM: `0.2`

## Схема из 5 блоков

Запрос идёт слева направо. Блок 5 — не шаг пайплайна, а способ показать результат снаружи. Аудит пишется всегда, в том числе при сбое LLM.

```text
[1. API] → [2. Guards] → [3. Triage] → [4. Audit] → [5. Deploy]
 FastAPI     валидация      OpenAI        SQLite      Docker
 POST        + лимит        temp 0.2      tickets     публичный URL
```

| Блок | Роль | Технология | Ответственность |
|---|---|---|---|
| 1. API | Контракт | FastAPI `POST /triage` | Принимает JSON, отдаёт строго 4 поля ответа. |
| 2. Guards | Надёжность | Pydantic + rate limit | Длина `text` 1–2000, обязательные поля, N запросов/мин на `client_id`. |
| 3. Triage | Классификация | OpenAI, temperature 0.2 | Категория + черновик. Ломаный JSON или сбой → эскалация. |
| 4. Audit | История | SQLite `tickets` | Пишет каждый запрос: успех, отказ LLM, ошибка парсинга. |
| 5. Deploy | Показ | Docker + публичный URL | Путь A: хостинг. Путь B: локально + видео/скрины. |

## Поток запроса

| Шаг | Что происходит | Если сломалось |
|---|---|---|
| Вход | JSON: `text`, `channel`, `client_id` | 422: нет `text` / длина вне 1–2000 |
| Лимит | Считаем запросы за минуту по `client_id` (память или SQLite) | 429: слишком часто |
| LLM | Классификация + `draft_reply`, JSON-режим, temperature 0.2 | `escalate=true`, шаблон «передано оператору», `error` в БД |
| Парсинг | Строгая схема: category, draft, confidence, escalate | Тот же fallback, если модель сломала формат |
| Аудит | INSERT в `tickets` до ответа клиенту | Ошибка БД — 500 (отдельный сбой инфраструктуры) |
| Ответ | 200 + ровно 4 поля контракта | Никогда не отдаём сырой текст модели наружу |

**Правило эскалации.** Мало данных, низкая уверенность, сбой OpenAI или невалидный JSON модели — всегда `escalate=true` и черновик-шаблон. Нельзя уверенно выдумывать факты, которых нет во входном `text`.

## Контракт

### Вход `POST /triage`

| Поле | Правило |
|---|---|
| `text` | string, обязательно, 1–2000 |
| `channel` | string-метка: `email` \| `form` \| `chat` |
| `client_id` | string, ключ лимита |

### Выход 200

| Поле | Правило |
|---|---|
| `category` | `billing` \| `support` \| `complaint` \| `other` |
| `draft_reply` | 1–6 предложений, только по `text` |
| `confidence` | `high` \| `medium` \| `low` |
| `escalate` | `true` если low / ошибка / мало данных |

## Критерии «готово»

MVP закрыт, когда каждый пункт ниже проверяется одним запросом или одним взглядом в БД / README. Без RAG, без живых каналов, без лишних endpoint.

| ID | Критерий | Как проверить | Блокер? |
|---|---|---|---|
| D1 | `POST /triage` принимает и отдаёт контракт | Postman: 200, ровно 4 поля, типы верные | Да |
| D2 | Категория из 4 значений и совпадает с текстом | 4 фикстуры: оплата / поломка / жалоба / мусор | Да |
| D3 | Черновик не обещает фактов вне `text` | Короткий vague-текст не содержит выдуманных сумм/дат | Да |
| D4 | Мало данных → `low` + `escalate=true` | Текст вроде «помогите» | Да |
| D5 | Сбой LLM / ломаный JSON → шаблон оператору | Неверный ключ или мок битого ответа | Да |
| D6 | Валидация длины и обязательности `text` | Пустой `text` и 2001 символ → 422 | Да |
| D7 | Ключ OpenAI только из env | В репозитории нет ключа | Да |
| D8 | Лимит N/мин на `client_id` | N+1 запрос за минуту → 429 | Да |
| D9 | Каждый вызов пишется в `tickets` | Есть строка после успеха и после fallback (`error` при сбое) | Да |
| D10 | Публичный показ | Путь A: URL + curl. Иначе путь B: видео + скрины + README | Да |

## Скоуп

**Входит:** один `POST /triage`, SQLite, Docker, README с шагами деплоя. Опционально `GET /health`. Эвристика: если модель сказала `high`, но `text` короткий — понизить до `low`.

**Не делаем:** живые почта/форма/чат, RAG, админка, Redis, больше четырёх категорий, отдельные endpoint истории.
